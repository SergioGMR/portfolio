## Vercel Hobby

The user confirmed Hobby. This implementation measures ordinary visits and available referrers only. It sends no custom events, contact addresses, free text, custom properties or synthetic pageviews for CV/contact clicks. A contact-link click is not a confirmed message or lead. CV downloads and external-project clicks remain unmeasured conversion actions.

`astro.config.ts` enables the existing adapter's Web Analytics integration only when `VERCEL_ENV === 'production'`. Local development, ordinary local builds and Vercel preview builds do not inject it. The installed `@astrojs/vercel@11.0.11` directly injects the official `/_vercel/insights/script.js`; no analytics SDK dependency was added. Verify this behavior again when updating the adapter: [Astro's adapter documentation](https://docs.astro.build/en/guides/integrations-guide/vercel/#webanalytics) distinguishes the legacy configuration from newer SDK component integrations.

[The Vercel plan documentation](https://vercel.com/docs/analytics/limits-and-pricing) lists the Hobby allowance, reporting window and lack of custom events. Check the current dashboard and current limits before interpreting missing data. No paid feature, plan upgrade or dashboard activation was performed here.

Provider steps require explicit authorization: enable Web Analytics for the correct project if it is not already enabled, deploy the reviewed change, and verify that a production page loads the official script and that an ordinary visit appears in that project's dashboard. Script presence in a local build does not prove successful collection. Browser blockers can suppress collection.

## Local evidence and remaining checks

The build verifier checks initial single-language HTML on all indexable routes, exact metadata and canonical URLs, reciprocal alternates, genuine language links, stable schema identity, factual project text, internal links/anchors, adapter HTML copies, sitemap completeness, noindex 404, the social image (JPEG for home and terms, per-project WebP cards for case studies), unchanged canonical PDF bytes and the absence of the legacy 2024 PDF files. The CV PDFs are regenerated from `docs/cv/*.html` with `bun run cv:build` (headless Chromium, document Info set to the legal name; set `CV_CHROME_PATH` to use a specific browser binary, since the generic `CHROME_PATH` belongs to the Lighthouse script); after regenerating, update `canonicalPdfSha256` in the verifier.

Structured data is one JSON-LD object per page (no `@graph`): the localized Person node is embedded in full on the home page (`mainEntity`), case studies and terms pages (`author`), and the home `ProfilePage` is `isPartOf` a `WebSite` node; every page carries `dateModified` from `PAGE_LAST_MODIFIED`. Whether Google uses the nested `WebSite` for site names is unverified until the Rich Results Test runs on the deployed URL. Case-study social cards are WebP files built with `getImage` (declared type and real size, checked by the verifier against the emitted file; sources smaller than 1200x630 are not enlarged); home and terms keep `/og.jpg`. Head tags use `name` for `twitter:*`, and the icon set is `favicon.ico` (32), `favicon-96x96.png`, `apple-touch-icon.png` (180, upscaled from the 128px logo) and the existing AVIF. The apple touch icon keeps the logo's transparent corners, which iOS renders on black.

Every built page carries a hashed `<meta http-equiv="content-security-policy">` (Astro `security.csp`; `script-src`/`style-src` allow `'self'` plus hashes, no `'unsafe-inline'`, so inline handlers and `style=` attributes are not allowed). Astro hashes the scripts and styles it processes but not `is:inline` scripts: their hashes come from `src/lib/csp.ts` at config time, and the verifier fails the build if any inline script or style in the output lacks a hash. The policy is not enforced by `astro dev`, `frame-ancestors` cannot be set in a meta tag (`X-Frame-Options` stays in `vercel.json`), and `/_vercel/insights/script.js` exists only in production builds (`VERCEL_ENV=production`); it is covered by `'self'` and was not exercised locally. The verifier also fails the build when something would make a browser ignore the meta: anything but whitespace and comments between the doctype, `<html>` and `<head>` (including U+FEFF); an element other than meta, link, title, script, style, noscript or template (so no `<base>`), text, self-closing syntax on a non-void element or a stray end tag (`</body>`, `</br>`) in head before the meta; a `<link>` to another origin before the meta; and `&` in the policy text, which a browser decodes but the verifier reads raw.

It does not cover all 22 routes, desktop behavior or field performance.
